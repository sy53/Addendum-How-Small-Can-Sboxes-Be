# Addendum to *How Small Can S-boxes Be?* — Code and Results

This repository contains research code and Verilog circuit files associated with the paper **“Addendum to How Small Can S-boxes Be?”** It includes the SAT-based search model used to seek low-latency S-box circuits and Verilog circuit implementations for six lightweight-cipher S-boxes.

> **Artifact status:** this repository is currently a code-and-results snapshot. It does not yet provide a fully automated, one-command reproduction of every result in the paper. See [Reproducibility](#reproducibility) for details.

## Paper

Yu Sun, Lixuan Wu, Chenhao Jia, Tingting Cui, Kai Hu, and Meiqin Wang, “Addendum to How Small Can S-boxes Be?”, *IACR Transactions on Symmetric Cryptology*, 2025(2), pp. 192–205, 2025.

- [DOI: 10.46586/tosc.v2025.i2.192-205](https://doi.org/10.46586/tosc.v2025.i2.192-205)
- [IACR Cryptology ePrint Archive, Report 2025/961](https://eprint.iacr.org/2025/961)

The work adapts the SAT-aided search tool from *How Small Can S-boxes Be?* to prioritize latency first and area second. The paper reports lower-latency implementations for the S-boxes used in LBlock, Piccolo, SKINNY-64, RECTANGLE, PRESENT, and TWINE.

## Repository contents

### Search and analysis code

| Path | Purpose |
| --- | --- |
| `array_main.py` | Builds the SAT model for S-box circuits with bypass and gate-depth constraints. |
| `sat.py` | Provides CNF constraint helpers, writes DIMACS files, invokes an external SAT solver, and parses its output. |
| `espresso.py` | Generates minimized constraints by invoking the external Espresso logic minimizer. |
| `basic_sbox.py` | Computes S-box properties, including DDT, LAT, differential uniformity, linearity, and algebraic degree. |
| `print.py` | Parses and verifies SAT solutions and converts them to circuit representations. |
| `print_tree.py` | Draws a circuit graph using NetworkX and Matplotlib. |
| `graph2verilog.py` | Defines two callable Verilog generators for stored circuit descriptions. |

### Verilog results

The `res/` directory contains combinational Verilog implementations and testbenches for the following S-boxes:

| Directory | S-box | Implementation files | Testbench |
| --- | --- | --- | --- |
| `res/sbox_lblock/` | LBlock S0 | `sbox_lblock1.v`–`sbox_lblock5.v` | `sbox_lblock_tb.v` |
| `res/sbox_piccolo/` | Piccolo | `sbox_piccolo1.v`–`sbox_piccolo5.v` | `sbox_piccolo_tb.v` |
| `res/sbox_present/` | PRESENT | `sbox_present1.v`, `sbox_present5.v` | `sbox_present_tb.v` |
| `res/sbox_rectangle/` | RECTANGLE | `sbox_rectangle1.v`–`sbox_rectangle5.v` | `sbox_rectangle_tb.v` |
| `res/sbox_skinny/` | SKINNY-64 | `sbox_skinny1.v`–`sbox_skinny5.v` | `sbox_skinny_tb.v` |
| `res/sbox_twine/` | TWINE | `sbox_twine1.v`, `sbox_twine5.v` | `sbox_twine_tb.v` |

Using the labels adopted in the paper, the numeric suffix identifies the source or method: `1` corresponds to `JPST17`, `2` to `Sto16`, `3` to `LWH+21`, `4` to `JCL+25`, and `5` to the circuits generated by our method.

ModelSim/Questa project files, compiled libraries, and waveform files are intentionally not included. They are generated artifacts and can be recreated from the Verilog circuit and testbench files.

## Requirements

Use Python 3 and install the following dependencies yourself:

Python packages:

- NetworkX
- Matplotlib

External executables:

- Kissat, available as `kissat` on `PATH`
- Espresso logic minimizer, available as `espresso` on `PATH`

The S-box property helpers in `basic_sbox.py` use only the Python standard library. NetworkX and Matplotlib are imported transitively by the search program through its visualization module.

The SAT-output parser expects standard `s SATISFIABLE` / `s UNSATISFIABLE` and `v ...` lines. The provided search path is configured for Kissat; other solvers would require a separately tested command-line adapter.

The current scripts invoke external commands through the shell and use Unix commands such as `mkdir` and `rm`. A Unix-like environment is therefore the safest choice until the command runner is made platform-independent. The Verilog files can be used with a simulator or synthesis tool of your choice; such tools are not dependencies of the Python search code.

## Basic usage

Run commands from the repository root.

### Run a SAT search

Candidate S-boxes and example parameter sets are listed in the `if __name__ == '__main__'` block of `array_main.py`. The example S-box calls are currently commented out, so running the script as provided only prints `finish!`.

```bash
python array_main.py
```

To launch a search, first install Kissat and Espresso, then enable exactly one appropriate call to `sbox_value_with_bp(n, g, d, sbox)` in `array_main.py`. Review the parameters before running: searches may take hours or days, and the present code permits a five-day solver timeout. Temporary CNF and Espresso files are created under `SAT/` and `ESPRESSO/`.

The arguments to `sbox_value_with_bp(n, g, d, sbox)` are:

- `n`: the input and output bit width of the S-box;
- `g`: the number of gates in the candidate circuit;
- `d`: the latency complexity;
- `sbox`: the S-box lookup table, represented as a sequence of output values.

## Reproducibility

This repository provides the source code used to search for implementations and the corresponding Verilog designs released with the paper. The search flow can be rerun after installing the dependencies listed above and selecting the desired S-box experiment in `array_main.py`. Because dependency versions are not pinned and the search relies on external tools, a new run is not expected to reproduce the generated files bit-for-bit; its purpose is to search for functionally equivalent candidate implementations under the selected constraints.

The supplied Verilog testbenches exercise all 16 possible inputs of each 4-bit S-box and can be used for functional simulation. For rigorous validation, compare the output of each implementation with the corresponding S-box truth table for every input value.

Reproducing the exact synthesis numbers requires a compatible synthesis environment and the same standard-cell library, process corner, constraints, and tool settings used in the paper. Commercial EDA software and licensed standard-cell libraries are not redistributed in this repository.
